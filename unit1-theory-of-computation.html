Unit I — Automata · Finite Automata · Regular Expressions · Non-Regular Languages

Machines with no memory but their state.

This unit builds one idea in four costumes: a set of strings (a language) can be described by a machine (DFA/NFA/ε-NFA) or by an algebra (regular expression) — and all four descriptions have exactly the same power. Then the pumping lemma shows where that power ends.

Textbook: Hopcroft–Motwani–Ullman (T1)Ch 1 (1.1, 1.5) · Ch 2 (2.1–2.5) · Ch 3 (3.1, 3.2.2, 3.2.3, 3.3) · Ch 4 (4.1)

§ 01Why Study Automata Theory?

Automata theory is the study of abstract computing devices ("machines") and the problems they can solve. It matters for two reasons: it has direct applications, and it defines the exact limits of computation.

  • Finite automata model real systems: software for designing/verifying digital circuits, lexical analyzers in compilers, text scanners searching large bodies of text (grep, web search), and protocol/embedded-system verification — any system that is naturally in one of a finite number of states (e.g., an on/off switch, a network protocol handshake).
  • Grammars (Unit II) model the structure of programming and natural languages; parsers are built from them.
  • Limits of computation: the theory distinguishes what is decidable vs undecidable (Turing machines, Unit III) and tractable vs intractable. Knowing a problem is unsolvable or infeasible tells you to change the problem, not fight it.
  • A hierarchy of machine power: finite automata ⊂ pushdown automata ⊂ Turing machines — each unit of this course climbs one rung.

§ 02Central Concepts of Automata Theory

Definitions — memorise verbatim
  • Alphabet (Σ): a finite, non-empty set of symbols. E.g., Σ = {0,1} (binary), Σ = {a,…,z}.
  • String (word): a finite sequence of symbols from Σ. The empty string ε has zero symbols. |w| = length of w (|ε| = 0).
  • Powers of an alphabet: Σk = all strings of length k over Σ; Σ0 = {ε}; Σ* = Σ⁰ ∪ Σ¹ ∪ Σ² ∪ … (all strings); Σ⁺ = Σ* − {ε}.
  • Concatenation: xy = symbols of x followed by symbols of y; εw = wε = w.
  • Language L: any subset of Σ* — a set of strings. Can be finite, infinite, ∅ (empty language) or {ε} (note: ∅ ≠ {ε}).
  • Problem ↔ language: deciding membership "is w ∈ L?" is the formal version of a yes/no computational problem.

Example languages over {0,1}: the set of strings with an equal number of 0s and 1s; the set of binary representations of primes; Σ* itself.

Exam pointerTwo chronic slips: (1) ε is a string, ∅ is a language, {ε} is a language containing one string; (2) Σ* is always infinite (for non-empty Σ), but every string in it is finite.

§ 03Deterministic Finite Automata (DFA)

Formal definition A DFA is a 5-tuple A = (Q, Σ, δ, q₀, F):
  • Q — finite set of states
  • Σ — input alphabet
  • δ : Q × Σ → Q — transition function: exactly one next state for every (state, symbol)
  • q₀ ∈ Q — start state
  • F ⊆ Q — set of accepting (final) states

Extended transition function & language

Definitions
δ̂(q, ε) = q    δ̂(q, wa) = δ( δ̂(q, w), a )

L(A) = { w | δ̂(q₀, w) ∈ F }

δ̂ processes a whole string; A accepts w iff processing w from q₀ lands in an accepting state. A language accepted by some DFA is called a regular language.

Worked example — strings ending in 01

L = {w ∈ {0,1}* | w ends in 01}. Design by state = what I remember: q₀ "no useful suffix", q₁ "just saw a 0 (possible start of 01)", q₂ "just saw 01" (accept).

δ01
→ q₀q₁q₀
q₁q₁q₂
* q₂q₁q₀

Trace of 1101: q₀ →1→ q₀ →1→ q₀ →0→ q₁ →1→ q₂ ∈ F → accepted.

Design recipe (works for most exam DFAs)Decide what finite information suffices to answer "accept?" at the end — that information is your state set. Common families to practise: strings containing a substring; ending/beginning with a pattern; number of a's mod k; even/odd counts (product construction for two conditions).

§ 04Nondeterministic Finite Automata (NFA)

Formal definition An NFA is a 5-tuple (Q, Σ, δ, q₀, F) where δ : Q × Σ → 2Q — a (state, symbol) pair maps to a set of states (possibly empty). The machine may be in several states at once; it accepts w if any sequence of choices ends in an accepting state.
  • Think of it as "guess and verify" or as running all threads in parallel; a dead branch (δ = ∅) simply dies.
  • δ̂(q, wa) = ⋃p ∈ δ̂(q,w) δ(p, a);  L(A) = { w | δ̂(q₀, w) ∩ F ≠ ∅ }.
  • NFAs are easier to design but no more powerful than DFAs (§05).

Same language, NFA style — strings ending in 01

Stay in q₀ on anything; nondeterministically guess "the final 01 starts now":

δ01
→ q₀{q₀, q₁}{q₀}
q₁∅{q₂}
* q₂∅∅

Three states instead of a "smart" DFA — the classic illustration that nondeterminism buys convenience, and sometimes exponentially fewer states (e.g., "k-th symbol from the end is 1" needs n+1 NFA states but 2ⁿ DFA states).

§ 05NFA → DFA: The Subset Construction

Theorem (equivalence)For every NFA N there is a DFA D with L(D) = L(N). Hence NFAs accept exactly the regular languages.

Construction

  • DFA states = subsets of the NFA's states (only the reachable subsets are needed in practice — "lazy evaluation").
  • Start state = {q₀}.  δD(S, a) = ⋃p∈S δN(p, a).  Accepting: any S containing an NFA accepting state.
  • Worst case 2ⁿ states; usually far fewer.
Worked example — convert the §04 NFA
DFA state01
→ {q₀}{q₀,q₁}{q₀}
{q₀,q₁}{q₀,q₁}{q₀,q₂}
* {q₀,q₂}{q₀,q₁}{q₀}

Rename {q₀}→A, {q₀,q₁}→B, {q₀,q₂}→C — and you get exactly the DFA of §03. Only 3 of the 2³ = 8 subsets were reachable.

Exam pointerShow the table being built breadth-first from {q₀}; stop when no new subsets appear. Mark accepting subsets. Proof idea (if asked): induction on |w| that δ̂D({q₀}, w) = δ̂N(q₀, w).

§ 06An Application: Text Search

Finding occurrences of keywords in large text is a pure automata problem — the reason grep-style tools are fast.

  • To search for a set of keywords, build an NFA: a start state q₀ with a self-loop on every symbol of Σ (skip any prefix), plus one linear chain of states per keyword spelling it out; the chain's last state accepts.
  • Example — keywords web and ebay: q₀ loops on Σ; chain q₀→(w)→q₁→(e)→q₂→(b)→q₃*, and chain q₀→(e)→q₄→(b)→q₅→(a)→q₆→(y)→q₇*.
  • Convert to a DFA with the subset construction. A useful fact: for keyword NFAs of this shape, the DFA has the same number of states as the NFA — no blow-up — so scanning is one table lookup per input character (O(1) per character, no backtracking).
  • This is how lexical analyzers and simple search engines process text in a single left-to-right pass.

§ 07Finite Automata with ε-Transitions (ε-NFA)

DefinitionAn ε-NFA is (Q, Σ, δ, q₀, F) with δ : Q × (Σ ∪ {ε}) → 2Q — the machine may jump between states without consuming input. Convenient for building automata compositionally (it's the machine form regular expressions compile to, §09).

ε-closure

Definition
ECLOSE(q) = all states reachable from q using ε-transitions only (including q itself)

Worked example — decimal-number sketch / a*b*c*

L = a*b*c*: states q₀ →ε→ q₁ →ε→ q₂ with self-loops a on q₀, b on q₁, c on q₂; q₂ accepts.

  • ECLOSE(q₀) = {q₀, q₁, q₂} — so ε alone is accepted (correct: ε ∈ a*b*c*).
  • To process symbol a from a state set S: take ε-closure, follow a-transitions, take ε-closure again. The modified subset construction with ε-closures converts any ε-NFA to a DFA — start state ECLOSE(q₀) — so ε-NFAs also accept exactly the regular languages.
Exam pointerWhen converting ε-NFA → DFA, the two places students lose marks: forgetting the closure after the symbol move, and forgetting that the start state is the closure of q₀, not {q₀}.

§ 08Regular Expressions

An algebraic notation for the same languages the automata accept — "declarative" (describe the strings) rather than "operational" (describe the machine).

Inductive definition Basis: ε and ∅ are REs (L(ε)={ε}, L(∅)=∅); each symbol a ∈ Σ is an RE (L(a)={a}).
Induction: if E, F are REs, so are
  • E + F (union): L(E+F) = L(E) ∪ L(F)
  • EF (concatenation): L(EF) = L(E)L(F)
  • E* (Kleene closure): L(E*) = ⋃i≥0 L(E)i — zero or more copies
  • (E) — grouping

Precedence: * highest, then concatenation, then +  (so 01* + 1 means (0(1*)) + 1).

§ 09Finite Automata and Regular Expressions Are Equivalent

Kleene's theorem (the unit's spine)A language is accepted by a DFA ⇔ by an NFA ⇔ by an ε-NFA ⇔ it is denoted by a regular expression. All four define the class of regular languages.

RE → ε-NFA (Thompson-style construction)

Build by structural induction; each sub-expression becomes a gadget with one start and one accepting state:

  • Basis: for a — two states joined by an a-edge; for ε — an ε-edge; for ∅ — no path.
  • E + F: new start with ε-edges into E's and F's starts; their accepting states ε-jump to a new accepting state.
  • EF: ε-edge from E's accepting state to F's start.
  • E*: new start/accept; ε-edges allowing skip (zero copies) and loop-back (repeat).

DFA → RE

  • State elimination (the exam-practical method): remove states one at a time, replacing paths through the removed state s by expressions — an edge p→q gains Rps (Rss)* Rsq. When only start and one accepting state remain, read the RE off the surviving edges. Repeat per accepting state and union the results.
  • Inductive (R⁽ᵏ⁾) method: Rij(k) = paths from i to j through intermediate states ≤ k, built by Rij(k) = Rij(k−1) + Rik(k−1)(Rkk(k−1))*Rkj(k−1) — correct but bulky; know that it exists.
Mini exampleOne-state DFA: start = accept = q, loops on 0 and 1 → RE = (0+1)*. Two-state "ends in 1": eliminate nothing — accept-state analysis gives (0+1)*1 directly. Practise eliminating the middle state of the §03 DFA to recover (0+1)*01.

§ 10Applications of Regular Expressions

  • Lexical analysis: tokens of a programming language (identifiers, numbers, keywords) are specified as REs; tools like lex/flex compile them into a DFA that scans source code. E.g., identifier: letter (letter + digit)*.
  • Text search / UNIX tools: grep, editors, and validators. UNIX RE notation adds conveniences that are only shorthand — no extra power: character classes [a-z], dot . (any char), + (one or more), ? (zero or one), anchors.
  • Pattern description in real data: e.g., US phone numbers, dates, protocol tokens — each a small RE compiled to an automaton.
  • The pipeline in all cases: RE → ε-NFA → DFA → (optionally minimized) table-driven scanner.

§ 11Proving Languages Not Regular — The Pumping Lemma

A DFA has finitely many states, so on any long enough string it must repeat a state — and the loop between the repeats can be "pumped". Languages that can't tolerate pumping aren't regular.

Pumping lemma for regular languages

If L is regular, then ∃ a constant n (≥ number of DFA states) such that every w ∈ L with |w| ≥ n can be split as w = xyz with:

  1. y ≠ ε
  2. |xy| ≤ n
  3. for all k ≥ 0: x yᵏ z ∈ L (including k = 0, "pumping down")

How to use it — the adversary game

  1. Assume L is regular; the lemma hands you an unknown constant n.
  2. You choose one clever string w ∈ L with |w| ≥ n (make it depend on n).
  3. The adversary splits w = xyz obeying (1) and (2) — your argument must work for every legal split, so use |xy| ≤ n to pin down where y lives.
  4. You choose one k (usually 0 or 2) such that xyᵏz ∉ L. Contradiction ⇒ L not regular.
Exam pointerThe lemma proves only non-regularity; satisfying it does not prove a language regular. And you don't get to pick the split — quantifier order (∃n, ∀w, ∃split, ∀k… from the lemma's side) is the most-tested conceptual point.

§ 12Worked Non-Regularity Proofs

Proof 1 — L = { 0ⁿ1ⁿ | n ≥ 0 } (the canonical one)

Suppose L regular with pumping constant n. Choose w = 0ⁿ1ⁿ ∈ L, |w| ≥ n. Any split w = xyz with |xy| ≤ n puts y inside the 0-block: y = 0m, m ≥ 1. Pump down (k = 0): xz = 0n−m1ⁿ has fewer 0s than 1s ⇒ xz ∉ L. Contradiction. ∎

Proof 2 — L = { w | w has equal numbers of 0s and 1s }

Same choice w = 0ⁿ1ⁿ works: y = 0m (m ≥ 1) by |xy| ≤ n; xz has n−m zeros vs n ones — unbalanced ⇒ not in L. ∎ (Moral: reuse a hard "witness" string across related languages.)

Proof 3 — L = { ww | w ∈ {0,1}* }

Choose s = 0ⁿ1 0ⁿ1 ∈ L. Split forces y = 0m within the first 0-block (m ≥ 1). Pump to k = 2: 0n+m1 0ⁿ1. For this to be uu, both halves must be equal, but the string has odd asymmetry — its two 1s would need to end each half, giving halves 0n+m1 and 0ⁿ1, unequal since m ≥ 1 ⇒ not in L. ∎

Proof 4 — L = { 0i1j | i > j }

Choose w = 0n+11ⁿ. y = 0m, m ≥ 1. Pump down: xz = 0n+1−m1ⁿ, and n+1−m ≤ n ⇒ condition i > j fails ⇒ not in L. ∎ (Shows why k = 0 is in the lemma: pumping up would only add 0s and stay in L.)

Other standard non-regular languages to recognise on sight: {0i²}, {0p : p prime}, palindromes, balanced parentheses — all "require unbounded counting/matching", which finite states cannot do.
