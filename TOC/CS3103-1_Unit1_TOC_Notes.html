01

Why Study Automata · Central Concepts

Automata theory studies abstract computing machines and the problems they can solve. Why it matters: automata model software (lexical analyzers in compilers, text-search engines, protocol/circuit verifiers) and mark the limits of computation — the ladder finite automata → pushdown automata → Turing machines is exactly the ladder regular → context-free → computable languages that structures this whole course. Formal proofs (deductive, induction, contradiction) are the working language throughout.

02

Deterministic Finite Automata (DFA)

DFA A = (Q, Σ, δ, q₀, F) Q finite state set · Σ input alphabet · δ : Q × Σ → Q (exactly one next state — the "deterministic") · q₀ ∈ Q start state · F ⊆ Q accepting states.

Extended transition function δ̂: δ̂(q,ε)=q; δ̂(q,xa)=δ(δ̂(q,x),a) — process the string one symbol at a time. L(A) = { w : δ̂(q₀,w) ∈ F }. A DFA is specified by a transition diagram (states = circles, accept = double circles, start = arrow) or a transition table.

Solved Problem 1 — DFA for strings ending in 01 (Σ = {0,1})

DESIGN THINKING · The machine must remember only "how much of a final 01 have I just seen?" A = seen nothing useful · B = last symbol was 0 (half-way) · C = last two symbols were 01 → accept. δ: A—0→B (a 0 might begin 01) · A—1→A (a 1 restarts) · B—0→B (still ends in 0) · B—1→C (completed 01!) · C—0→B (…010: new 0 pending) · C—1→A (…011: dead end, restart). States = memory. A DFA's states are exactly the distinctions the language forces you to remember — nothing more.

Solved Problem 2 — even number of 0s AND even number of 1s

DESIGN THINKING · Two independent parities → remember the pair (parity of 0s, parity of 1s) → 2×2 = 4 states. EE (even,even) = start = accept · OE · EO · OO. A symbol 0 flips the first coordinate; a symbol 1 flips the second. Every 0-edge moves horizontally, every 1-edge vertically — the diagram is a square. Pattern to reuse: "count X mod m and Y mod n" ⇒ m·n states, one per remainder pair.

Solved Problem 3 — strings containing the substring 01

SOLUTION · Progress-toward-pattern states: q0 = nothing seen · q1 = a 0 seen (pattern half-done) · q2 = 01 has occurred (accept, and stay forever). δ: q0—1→q0, q0—0→q1 · q1—0→q1, q1—1→q2 · q2—0,1→q2 (a trap/absorbing accept: once the substring occurs it can't un-occur). Contrast with Problem 1: "ends with" states can fall out of acceptance; "contains" states never do. Same pattern, different exits.
Every DFA state must have exactly one outgoing edge per symbol — no missing moves, no choices. If your diagram has a state with no 1-edge, it's not a DFA (add a dead state if a move should reject).

03

Nondeterministic Finite Automata (NFA)

NFA A = (Q, Σ, δ, q₀, F) with δ : Q × Σ → 2^Q δ returns a set of states — zero, one, or many. The machine is in a set of states at once; a string is accepted if some choice sequence ends in F ("guess and verify").
DFANFA
δ outputOne stateA set of states (possibly ∅)
Missing movesNot allowedAllowed (that branch dies)
AcceptanceThe unique run ends in FSome run ends in F
PowerEqual — every NFA has an equivalent DFA (subset construction)
SizeMay need up to 2ⁿ statesOften exponentially smaller / easier to design

Solved Problem 4 — NFA for strings ending in 01, then convert to DFA

NFA DESIGN · Nondeterminism = guessing. q0 loops on 0,1 (reading the irrelevant prefix), and on a 0 also guesses "this is the final 01 starting now" → q1; q1 on 1 → q2 (accept). Three states, near-zero thought — compare with the DFA's careful case analysis in §02.

Subset (powerset) construction — NFA → DFA

DFA states = sets of NFA states. Start = {q₀}. For a set S and symbol a: δ_D(S,a) = ⋃_{q∈S} δ_N(q,a). Accepting: any set containing an NFA accept state. Build lazily — only sets actually reachable:

Conversion of Problem 4's NFA (rows appear in discovery order)

DFA state (set)on 0on 1accepting?
{q0} ← start{q0,q1} (loop + guess){q0}no
{q0,q1}{q0,q1}{q0,q2}no
{q0,q2}{q0,q1}{q0}yes (contains q2)

Only 3 of the 2³ = 8 possible subsets are reachable — and relabeling {q0}=A, {q0,q1}=B, {q0,q2}=C gives exactly the DFA of Solved Problem 1. The theory closes its own loop.

Subset construction is a near-certain 8/10-mark numerical. Show: the lazy table (start set, expand each new set per symbol), the accepting-set rule, and the reachable-states remark. Worst case 2ⁿ — quote the "ends with n-th symbol from the end = 0" family as the language forcing the blow-up.

04

ε-NFA — Epsilon Transitions & ε-Closure

ε-NFA: δ : Q × (Σ ∪ {ε}) → 2^Q The machine may jump between states without consuming input. Adds convenience (gluing machines together — see Thompson, §07), not power.

ε-closure(q) = all states reachable from q by ε-edges alone (q itself included, then follow ε-arrows transitively). Processing a symbol a from a state set S: take ε-closure of S, move on a, take ε-closure again.

Solved Problem 5 — the a*b*c* machine

MACHINE · q0 —a→ q0, q0 —ε→ q1 · q1 —b→ q1, q1 —ε→ q2 · q2 —c→ q2, F = {q2}. This accepts a*b*c*: any number of a's, then b's, then c's — the ε-edges let the machine silently "move on to the next phase". ε-CLOSURES · ECLOSE(q0) = {q0, q1, q2} (q0 → q1 → q2 by ε-chain) ECLOSE(q1) = {q1, q2} · ECLOSE(q2) = {q2} TRACE "abc" · start: ECLOSE(q0) = {q0,q1,q2} read a: only q0 moves → {q0}; close → {q0,q1,q2} read b: only q1 moves → {q1}; close → {q1,q2} read c: only q2 moves → {q2}; close → {q2} ∈ F → ACCEPT Also: ε itself is accepted (start closure already contains q2 ∈ F) — a*b*c* includes the empty string ✓. DFA CONVERSION (lazy) · A={q0,q1,q2}: a→A, b→{q1,q2}=B, c→{q2}=C B: a→∅(dead), b→B, c→C · C: a,b→dead, c→C · all of A,B,C accepting (contain q2).
Two classic ε mistakes: (1) forgetting q ∈ ECLOSE(q) always; (2) closing only once — the closure must be applied after every symbol move, and transitively (follow chains of ε-edges, not one hop).

05

Application — Text Search

Searching a document for keywords is automaton territory. To find occurrences of web or ebay in a character stream:

  • NFA design (trivial): a start state q1 looping on every character Σ, plus one chain per keyword: q1 —w→ q2 —e→ q3 —b→ q4 (accept "web"); q1 —e→ q5 —b→ q6 —a→ q7 —y→ q8 (accept "ebay"). The loop nondeterministically "guesses" where a keyword begins.
  • Then convert to a DFA via subset construction and run it: one state transition per input character, no backtracking — this is how grep-style tools and lexical analyzers achieve linear-time scanning.
  • Useful fact from the conversion: for keyword-NFAs of this shape, the DFA has the same number of states as the NFA — the exponential worst case doesn't bite here. Each DFA state remembers "which prefixes of which keywords are currently alive".
Expected short question: "Explain text search using finite automata" → draw the two-chain NFA, state the guess-the-start role of the Σ-loop, mention DFA conversion for backtrack-free linear scanning.
06

Regular Expressions

Regular expressions denote languages algebraically. Basis: ∅, ε, and a for each a ∈ Σ. Induction: if E, F are REs then so are E+F (union), EF (concatenation), E* (Kleene star = zero or more copies), (E). Precedence: * > concatenation > + — so 01* + 1 means (0(1*)) + 1.

Identities worth memorizing

∅ + L = L  ·  εL = Lε = L  ·  ∅L = L∅ = ∅  ·  ∅* = ε  ·  ε* = ε
L + L = L  ·  (L*)* = L*  ·  L(M+N) = LM+LN  ·  (ε + L)* = L*  ·  L*L* = L*

Solved Problem 6 — a battery of RE designs (Σ = {0,1})

a) Ends in 01: (0+1)*01 anything, then the mandatory suffix. (Same language as §02 P1 and §03 P4 — three formalisms, one language.) b) Contains 01: (0+1)*01(0+1)* the pattern somewhere in the middle. c) No two consecutive 1s: (0 + 10)* (1 + ε) every 1 must be followed by a 0 — chain blocks of "0" or "10" — except possibly one final 1. d) Even length: ((0+1)(0+1))* pairs of symbols, repeated. e) Even number of 0s: 1* (01*01*)* 1s are free; 0s consumed strictly in pairs, 1s allowed anywhere between. f) Third symbol from the right is 1: (0+1)* 1 (0+1)(0+1) the language whose DFA needs 2³ = 8 states but whose NFA/RE are tiny — the standard witness that NFAs can be exponentially smaller. g) At most one pair of consecutive 0s AND at most one pair of consecutive 1s — left as the hard master-check; attack it by cases on where the pairs sit.

Applications of regular expressions

  • Lexical analysis — tokens of a programming language (identifiers, numbers, keywords) are specified by REs; tools like lex compile them into a DFA scanner. E.g. identifiers: letter (letter + digit)*.
  • Text search / grep — UNIX REs add conveniences (character classes [a-z], ., ? = ε-or-one, + = one-or-more) but compile to the same automata.
  • Pattern description in data — e.g. recognizing addresses, dates, DNA motifs.
(0+1)* means "any string", not "0 or 1 repeated in a fixed choice"; and 0* + 1* ≠ (0+1)* — the left side is only all-0 strings or all-1 strings. Test any RE you write on: ε, 0, 1, 01, 10.

07

Equivalence: Finite Automata ↔ Regular Expressions

The pillar theorem of the unit: a language is regular ⟺ it is L(DFA) ⟺ L(NFA) ⟺ L(ε-NFA) ⟺ L(RE). Both directions are constructive:

RE → ε-NFA (Thompson / McNaughton–Yamada construction)

  • Each RE gets an ε-NFA with one start, one accept state, built by structural induction:
  • Basis: ε → two states joined by an ε-edge; a → two states joined by an a-edge; ∅ → two states, no edge.
  • E+F: new start with ε-edges into E's and F's starts; both accepts ε-jump to a new accept (parallel branches = choice).
  • EF: E's accept ε-jumps into F's start (series = sequence).
  • E*: new start/accept; ε-edges: start→E-start, E-accept→E-start (loop!), start→accept (zero copies), E-accept→accept.
SOLVED · (0+1)*01 step by step: 1. Machines for 0 and for 1 (one edge each). 2. Union (0+1): parallel wiring with ε in/out — 6 states. 3. Star (0+1)*: wrap with the loop-and-bypass ε skeleton — 8 states. 4. Concatenate machine for 0, then for 1: ε-glue in series — 12 states total. Every step is mechanical — which is exactly why compilers can do it. Convert onward to DFA via ε-closure subset construction (§04) and you land, once again, on the 3-state machine of §02.

DFA → RE, exam style: Arden's theorem + state equations

Arden: if P doesn't contain ε, then R = Q + RP has the unique solution R = QP* Write one equation per state (incoming edges), substitute, and crank until the accept state's expression has no state variables.
SOLVED · RE for "odd number of 1s" (DFA: A start, B accept; 0 loops on both; 1 toggles A↔B) Equations (each state = how you can arrive there): A = ε + A0 + B1 (start contributes ε) B = A1 + B0 Solve B by Arden (R = Q + RP with Q = A1, P = 0): B = A1(0)* Substitute into A: A = ε + A0 + A1(0)*1 = ε + A(0 + 1(0)*1) Arden again (Q = ε, P = 0 + 10*1): A = (0 + 10*1)* Answer (accept state B): L = (0 + 10*1)* 1 0* Read it: blocks that preserve parity (a 0, or a 1…0s…1 pair), then the one unmatched 1, then trailing 0s. Sanity tests: "1" ✓, "10" ✓, "11" ✗ (needs the pair) ✓.

The alternative textbook route is state elimination: remove states one by one, relabeling edges with REs; the final two-state picture reads off the answer. Know that it exists and its name; Arden is faster in exams.

08

Proving Languages Not Regular — the Pumping Lemma

Finite automata have finite memory; languages requiring unbounded counting can't be regular. The tool:

Pumping Lemma: L regular ⇒ ∃ constant p ≥ 1 such that every w ∈ L with |w| ≥ p splits as w = xyz with (1) y ≠ ε   (2) |xy| ≤ p   (3) xyⁱz ∈ L for all i ≥ 0 Intuition: a run of length ≥ p must revisit some state (pigeonhole over p states); the loop between the revisits is y — traverse it any number of times, the machine can't tell.

How to use it — the adversary game. The lemma is a one-way test used by contradiction: assume L regular; the adversary fixes p (unknown to you); you choose one clever w ∈ L, |w| ≥ p; the adversary splits w = xyz obeying (1),(2) — your proof must work for every legal split; you pick one pumping count i and show xyⁱz ∉ L. Contradiction ⇒ L not regular.

Solved Problem 7 — L = {0ⁿ1ⁿ : n ≥ 0} is not regular

xy (pumped)z
0…00ᵏ0ᵏ0ᵏ1…1 (p ones)
pumping y adds 0s but never 1s → count breaks → xy²z ∉ L
PROOF · Suppose L is regular with pumping constant p. Choose w = 0ᵖ1ᵖ ∈ L, |w| = 2p ≥ p. Let w = xyz be any split with |xy| ≤ p and y ≠ ε. Since |xy| ≤ p and the first p symbols are all 0s: y = 0ᵏ for some k ≥ 1 — the split has no freedom that matters; this is why w was chosen with the 0-block first. Pump with i = 2: xy²z = 0^(p+k) 1ᵖ. Now #0 = p+k > p = #1 → xy²z ∉ L. Contradiction with condition (3). Hence L is not regular ∎ (i = 0 works equally: 0^(p−k)1ᵖ ∉ L. State one; mentioning both shows command.)

Solved Problem 8 — L = { w : #0(w) = #1(w) } is not regular (closure shortcut)

PROOF BY CLOSURE · Regular languages are closed under intersection, and 0*1* is regular (it's an RE!). If L were regular, then L ∩ 0*1* = {0ⁿ1ⁿ : n ≥ 0} would be regular. But Problem 7 proved it isn't. Contradiction ⇒ L is not regular ∎ Lesson: before grinding a pumping argument, check whether intersecting/complementing into a known non-regular language kills it in two lines.

Solved Problem 9 — L = { 0^(i) 1^(j) : i > j } is not regular

PROOF · Assume regular, constant p. Choose w = 0^(p+1) 1ᵖ ∈ L (one more 0 than 1s, |w| ≥ p). |xy| ≤ p ⇒ y = 0ᵏ, k ≥ 1, entirely inside the 0-block. Pump down, i = 0: xz = 0^(p+1−k) 1ᵖ. Since k ≥ 1: p+1−k ≤ p ⇒ #0 ≤ #1 ⇒ xz ∉ L. ∎ Lesson: when the language is an inequality, pump in the direction that violates it — here pumping UP keeps i > j true forever, so only i = 0 finishes the proof. Choosing the pumping direction is half the marks.
Three proof-killing errors: (1) letting yourself choose the split — the adversary owns x,y,z; your argument must cover every legal split; (2) choosing w not in L or with |w| < p; (3) forgetting |xy| ≤ p, which is precisely what pins y inside your chosen leading block. Also: the lemma can never prove a language IS regular — satisfying it proves nothing.
