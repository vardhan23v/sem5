01

Definition · Transition Table · Diagram · δ̂

A DFA is a 5-tuple A = (Q, Σ, δ, q₀, F): finite state set Q, input alphabet Σ, transition function δ : Q × Σ → Q, start state q₀ ∈ Q, accepting states F ⊆ Q. The word deterministic lives entirely inside δ: for every state and every symbol there is exactly one next state — no choices, no gaps.

  • Transition diagram — circles = states, double circle = accepting, unlabeled arrow = start, labeled arrows = δ. Transition table — rows = states (→ marks start, * marks accepting), columns = symbols. Both encode δ; exams often ask for both.
  • Extended transition function δ̂ — δ lifted to whole strings: δ̂(q,ε) = q and δ̂(q,xa) = δ(δ̂(q,x),a). Read: to process xa, process x first, then take one more step on a.
  • Language: L(A) = { w ∈ Σ* : δ̂(q₀,w) ∈ F } — start at q₀, consume every symbol, accept iff you halt in F. Note the ε-corollary: ε ∈ L(A) ⟺ q₀ ∈ F.
A diagram where some state lacks an outgoing edge for some symbol is NOT a DFA. If a symbol should doom the string, route it to an explicit dead state (§05) — never leave it undrawn.
02

The 5-Step Design Recipe — use it on every problem

Ask: what must I remember?Reading left→right, the minimum info needed to decide at the end. This IS the design.
Name a state per memory valueWrite a one-line meaning for every state. If you can't state a meaning, the state is wrong.
Fill δ completelyFrom each state, for each symbol: how does the memory update? Every cell of the table gets exactly one entry.
Mark start & acceptsStart = "nothing read yet" memory. Accept = the memory values that mean "yes".
Test ruthlesslyAlways run: ε, single symbols, a shortest accepted string, a near-miss reject, one long mixed string.

Every solved problem below is written in exactly this shape: THINK (step 1) → STATES (step 2) → δ (step 3) → START/ACCEPT (step 4) → TEST (step 5). Copy the shape into your exam answers — the meanings table earns method marks even if an edge slips.

03

Family A — Suffix problems: "ends with …"

Solved 1 · L = strings over {0,1} ending in 01

THINK · Only the tail matters. At any moment I need: "how much of a final 01 have I just seen?" — 0, half (…0), or all (…01). Three memory values → three states. STATES · A = no progress (last symbol useless) · B = last symbol was 0 · C = last two were 01. δ · from A: 0→B (a 0 could begin the suffix), 1→A (a 1 can't). From B: 0→B (…00 still ends in 0), 1→C (01 completed!). From C: 0→B (…010 — a fresh 0 is pending), 1→A (…011 — progress destroyed). START/ACCEPT · start A ("nothing seen"); accept {C}. TEST · ε→A reject ✓ · "01"→A,B,C accept ✓ · "010"→…B reject ✓ · "1101"→A,A,B? no: 1→A,1→A,0→B,1→C accept ✓. The suffix pattern: states = progress levels of the suffix; the subtle edges are the FALL-BACKS (C on 0 goes to B, not A — the just-read 0 is reusable progress).

Solved 2 · ends with 00 (do the transfer)

Same skeleton, new suffix. States: q0 no progress · q1 last = 0 · q2 last two = 00 (accept). δ: q0: 0→q1, 1→q0 · q1: 0→q2, 1→q0 · q2: 0→q2 (…000 still ends 00!), 1→q0. Compare with Solved 1: the fall-backs differ because the suffix differs — q2 on 0 stays (extra 0s keep the suffix alive), whereas C on 0 dropped to B. Derive fall-backs from the suffix, never copy them.
04

Family B — Substring problems: "contains …"

Solved 3 · L = strings containing 01

THINK · Progress toward the pattern — but once found, it can never be un-found. Memory: not-started / half / done-forever. STATES · q0 = no 0 seen yet that could start 01 · q1 = pattern half-done (a 0 pending) · q2 = 01 has occurred — trap accepting state. δ · q0: 1→q0, 0→q1 · q1: 0→q1 (still pending), 1→q2 · q2: 0→q2, 1→q2 (absorb everything). ACCEPT · {q2}. TEST · "10"→q0,q1 reject ✓ · "100"→q1 reject ✓ · "1001…anything" accept ✓. Family signature: "ends with" states can fall OUT of acceptance; "contains" has a one-way door into a trap accept.

Solved 4 · contains 001 (longer pattern = KMP-style fall-backs)

STATES · s0 nothing · s1 seen 0 · s2 seen 00 · s3 = 001 occurred (trap accept). δ · s0: 0→s1, 1→s0 · s1: 0→s2, 1→s0 (a 1 after one 0 kills everything) · s2: 0→s2 (!), 1→s3 · s3: 0,1→s3. The star edge: s2 on 0 stays at s2 — after "000" the LAST two 0s are still a valid "00" prefix of the pattern. Fall-backs must answer: "what is the longest prefix of the pattern that is a suffix of what I've read?" — exactly the failure function of string matching. TEST · "0001" → s1,s2,s2,s3 accept ✓ · "0101" → s1,s0,s1,s0 reject ✓.
In substring DFAs the wrong reflex is sending s2 —0→ s1 "because a new 0 starts over". Overlaps mean progress is partially reusable. Always ask the longest-prefix-that-is-a-suffix question at every fall-back edge.
05

Family C — Prefix problems: "starts with …" (and the dead state)

Solved 5 · L = strings starting with 01

THINK · The first two symbols decide everything; after that nothing can change the verdict. Two irreversible outcomes → need a permanent YES (trap accept) and a permanent NO (dead state). STATES · S = nothing read · A = read exactly "0" so far (on track) · F = prefix confirmed, accept forever · D = prefix ruined, reject forever (dead). δ · S: 0→A, 1→D · A: 1→F, 0→D · F: 0,1→F · D: 0,1→D. ACCEPT · {F}. TEST · "0"→A reject ✓ (too short) · "01"→F ✓ · "0110…"→F ✓ · "1…anything" → D reject ✓. The dead state is not decoration — without it, δ would be partial and the machine wouldn't be a DFA at all.

Family D — Counting & Parity

Solved 6 · even number of 0s

THINK · Exact counts need unbounded memory — impossible. But count mod 2 needs one bit. Memory = parity of 0s so far. STATES · E = even 0s so far (start; ε has zero 0s = even → E accepts!) · O = odd. δ · a 0 toggles E↔O; a 1 self-loops (irrelevant symbol). ACCEPT · {E}. General law: "count X mod m" ⇒ exactly m states in a cycle driven by X, with all other symbols looping.

Solved 7 · even 0s AND even 1s (product construction, live)

THINK · Two independent parities ⇒ remember the PAIR ⇒ 2×2 = 4 states arranged as a square: 0-edges move horizontally, 1-edges vertically. ACCEPT · only EE (both even). Change the accepting set, same machine solves siblings: odd&odd → {OO}; even-0s OR even-1s → {EE,OE,EO} — see §09.

Family E — Length & Divisibility

Solved 8 · |w| divisible by 3

THINK · Memory = length mod 3. Three states q0,q1,q2 in a cycle; EVERY symbol advances the cycle (length doesn't care which symbol). δ: qᵢ —0,1→ q₍ᵢ₊₁₎ mod 3 · start q0 · accept {q0} (ε has length 0 ✓).

Solved 9 · binary numbers divisible by 3 — the crown jewel (live)

THINK · Memory = value mod 3 of the bits read so far. The magic update: appending bit b to a number with value v gives value 2v + b (shift left, add bit). So mod 3: new remainder = (2·r + b) mod 3 STATES · r0, r1, r2 = current remainder. Start r0 (empty prefix ≙ value 0). Accept {r0}. δ (crank the formula) · r0: 0→(0)%3=r0 · 1→(1)%3=r1 r1: 0→(2)%3=r2 · 1→(3)%3=r0 r2: 0→(4)%3=r1 · 1→(5)%3=r2 TEST · "110" = 6 → r0? 1:r1, 1:r0, 0:r0 ✓ accept · "101" = 5 → r1,r2,r2 reject ✓. Same recipe builds "divisible by k" for any k (k states) and any base. THE most-set design question of the unit.

Family F — At least · Exactly · At most (Σ = {a,b})

Solved 10 · at least two a's

THINK · Count a's, but saturate at 2 — beyond two, more a's change nothing. Memory: 0, 1, or ≥2 a's. STATES · q0 (zero a's) · q1 (one) · q2 (two or more — trap accept). δ: b self-loops everywhere; a marches q0→q1→q2; q2: a→q2. Accept {q2}.

Solved 11 · exactly one b

THINK · "Exactly" = at-least AND at-most ⇒ the counter needs an overflow state. Memory: 0 b's / 1 b / ≥2 b's. STATES · p0 (no b yet) · p1 (exactly one — ACCEPT) · p2 (too many — DEAD). δ: a loops on all; b: p0→p1→p2, p2→p2. Accept {p1}. Note both trap flavors in one machine: p2 is a dead reject; in Solved 10 q2 was a trap accept. §09 formalizes the difference.

Solved 12 · no two consecutive 1s (Σ={0,1})

THINK · A forbidden pattern (11) = "contains 11" complemented. Memory: safe / one-1-pending / doomed. STATES · t0 = last symbol not 1 (accept) · t1 = last symbol was a single 1 (accept — still legal!) · t2 = 11 occurred (dead). δ: t0: 0→t0, 1→t1 · t1: 0→t0, 1→t2 · t2: 0,1→t2. Accept {t0,t1}. TEST · ε ✓ · "0101" ✓ · "0110" → t0,t1,t2,t2 reject ✓.
09

Three Power Tools — Complement · Product · Dead vs Trap

Complement — free of charge

Given a DFA for L, the DFA for L̄ = Σ* − L is the same machine with F swapped: accept ↔ non-accept. Solved 12 done backwards: build "contains 11" (easy, Family B), then flip accepts. Works ONLY on a complete DFA — flip a diagram with missing edges and the missing strings are silently wrong. Complete the machine (add the dead state) first.

Product construction — AND / OR of languages

For L₁ ∩ L₂ or L₁ ∪ L₂: run both DFAs "in parallel" — states are pairs (p,q), δ((p,q),a) = (δ₁(p,a), δ₂(q,a)). Accept pairs where both accept (∩) or at least one accepts (∪). The parity square of §06 IS the product of two 2-state parity machines — |Q| = |Q₁|·|Q₂|.

Dead state vs trap accept

Both are absorbing (all edges loop back); they differ only in membership of F. Dead = permanent NO ("prefix ruined": §05 D, §08 p2). Trap accept = permanent YES ("pattern found": §04 q2/s3). Every "starts with", "contains", "at most" machine has one; name which kind in your answer.

Combined-condition questions ("even 0s AND ends with 1") are product constructions in disguise: design each condition separately, then pair states. Saying the word "product construction" + giving |Q₁|·|Q₂| earns method marks before you draw anything.

Drill Sheet — 10 problems that close the unit

Design each fully (five recipe steps, meanings table, complete δ, tests). Peek at the hints only after committing an answer.

THE DRILL — answers hidden inside
  1. Ends with 110. 4 progress states; fall-backs: after failure, keep the longest reusable suffix (e.g. from "11" on 1 stay at "11").
  2. Contains 010. 4 states; s("01") on 0 → accept-trap; s("01") on 1 → back to s("") — no, careful: "011"+… restart, but "01"+"0" hits; verify with "0110 10".
  3. Starts and ends with the same symbol (|w| ≥ 1). Branch on first symbol into two 2-state "last symbol" trackers: 5 states incl. start.
  4. Binary numbers divisible by 4. Shortcut: ends with 00 (Solved 2 with accept tweak) — or 4 remainder states; both correct, say why they agree.
  5. |w| mod 3 = 1. Solved 8's cycle, accept {q1}.
  6. Even a's AND odd b's. Parity square, accept {EO}.
  7. At most two 0s. Counter q0,q1,q2 all accepting + dead q3 on the third 0.
  8. Every 1 is immediately followed by a 0. t0 safe(accept) · t1 owe-a-0 · dead on 1 from t1; ε accepts.
  9. Does NOT contain 000. Build contains-000 (4 states), flip accepts — after completing the machine.
  10. (0+1)*: strings whose 2nd symbol is 1. S → (any) → check position 2 → trap accept/dead; 4–5 states. Positions = prefix family.
