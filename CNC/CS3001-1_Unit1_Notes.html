01

Data Communications

Data communications is the exchange of data between two devices via some form of transmission medium (wire, cable, air), governed by rules called protocols. Data = information in an agreed form between the parties; effectiveness depends on four characteristics:

  • Delivery — data must reach the correct destination, and only the intended device/user.
  • Accuracy — delivered without alteration; corrupted data is unusable.
  • Timeliness — arrives in time to be useful (audio/video → "real-time" delivery, in production order, without significant delay).
  • Jitter — variation in packet arrival times; uneven delays ruin streaming even if average delay is fine (e.g. video packets alternating 30 ms/40 ms gaps).

Five components of a data communication system

  1. Message — the information (text, numbers, images, audio, video).
  2. Sender — device that sends (computer, phone, camera).
  3. Receiver — device that receives.
  4. Transmission medium — physical path (twisted-pair, coax, fiber, radio waves).
  5. Protocol — the rules; without it devices may be connected but cannot communicate — like two people speaking different languages. A protocol defines what is communicated, how, and when (syntax, semantics, timing).

Data representation

Text (Unicode/ASCII bit patterns) · Numbers (binary, not ASCII — for direct arithmetic) · Images (pixel matrix; RGB/YCM color coding or grayscale) · Audio (continuous by nature) · Video (picture sequence).

Data flow (direction of transmission)

Simplex
SR

One-way only. Full channel capacity in one direction. Keyboard → CPU, TV broadcast.

Half-Duplex
AB

Both transmit, but not simultaneously — the link alternates. Full capacity is available to whichever side is sending. Walkie-talkies, CB radio.

Full-Duplex
AB

Both transmit and receive at once — two physical paths, or capacity split between directions. Telephone network.

Networks & Network Types

A network is the interconnection of a set of devices capable of communication — hosts / end systems (computers, phones, servers) and connecting devices (routers, switches, modems) — joined by wired or wireless links.

Network criteria

  • Performance — measured by throughput and delay; we want more of the first, less of the second, and they often trade off (heavier traffic → higher throughput of the network overall but longer queues → more delay).
  • Reliability — failure frequency, recovery time, robustness in catastrophe.
  • Security — protection against unauthorized access and damage; policies for recovery from breaches and data loss.

LAN — Local Area Network

  • Privately owned; a single office, building, or campus. Each host has an address unique within the LAN.
  • Evolution: early LANs = one common cable, every packet broadcast to all (received by all, kept by the addressee, dropped by others). Today a switch forwards each packet only to its destination port → several pairs communicate simultaneously with no collisions between them.
  • Typical rates 100 Mbps–10 Gbps.

WAN — Wide Area Network

  • Spans towns → the world; normally built and run by communication companies and leased by users.
  • Point-to-point WAN — two connecting devices joined by a medium (cable/air), e.g. a leased line between two routers of one company.
  • Switched WAN — more than two ends; a mesh of switches — the backbone of global communication today.
  • Core contrast: a LAN interconnects hosts; a WAN interconnects connecting devices.

Internetwork → the Internet

Connecting ≥2 networks makes an internetwork (internet): e.g. two office LANs + a point-to-point WAN between them (router at each side). A host on one LAN reaches a host on the other through LAN→WAN→LAN, routers choosing the path. The Internet (capital-I) is the specific global internetwork: backbones (large ISPs) connected at peering points, provider networks paying backbones, customer networks at the edge paying providers — all speaking TCP/IP.

Connection-Oriented vs Connectionless Service

📞
Connection-Oriented
"TELEPHONE MODEL" · TCP, virtual-circuit networks

Three phases: setup → data transfer → teardown. A logical connection (state/path) exists first; packets follow it and arrive in order; delivery can be acknowledged → reliability. Cost: setup latency + per-connection state in the network.

✉️
Connectionless
"POSTAL MODEL" · UDP, IP, datagram networks

No setup. Each packet is independent: full destination address inside, possibly different routes, possible reordering/loss/delay. Low overhead and instant start; reliability, if needed, is layered on top (e.g. TCP over IP).

Network Devices

〰️
Modem
MOdulator + DEModulator

Converts digital data ↔ analog signals so computer data can cross analog media (telephone line, cable TV plant). Sender modulates, receiver demodulates. DSL modems split voice/data bands on the same line; cable modems share the CATV coax.

🔀
Hub
PHYSICAL LAYER (L1)

Multiport repeater: regenerates the signal and floods it out every port. No addressing, no filtering → one big collision domain, wasted bandwidth, zero privacy. Obsolete; replaced by switches.

🔁
Switch
DATA-LINK LAYER (L2)

Learns source MACs into a switching table, then performs filtering + forwarding: frame goes only to the destination's port. Each port = its own collision domain; multiple pairs talk at once; unknown destinations are flooded until learned.

🧭
Router
NETWORK LAYER (L3)

Joins different networks. Routes by IP address + routing table (best next hop). Has an IP + MAC per interface; rewrites link-layer addresses hop by hop; blocks broadcasts (separates broadcast domains).

Physical Layer — Digital Signals & Transmission Impairment

Digital signals

Data is encoded using a discrete number of voltage levels L; each level carries log₂ L bits.

bits per level = log₂ L   ·   8 levels → 3 bits/level If L isn't a power of 2, take ⌈log₂L⌉. Example: L = 4 → 2 bits per level.
  • Bit rate N — bits per second (bps).
  • Bit length — distance one bit occupies on the medium: bit length = propagation speed × bit duration (the wire-analog of wavelength).
  • A digital signal is a composite analog signal with theoretically infinite bandwidth; a real channel passes only part of it, so shape degrades — hence encoding rules and rate limits.
  • Transmission: baseband — digital signal sent as-is over a low-pass channel (dedicated medium: LANs); broadband — digital data modulated onto an analog carrier for a band-pass channel (modems).
SOLVED · A signal must send 6 Mbps and the hardware supports 8 levels. Required signal rate (baud)? S = N / log₂L = 6,000,000 / 3 = 2 Mbaud. (Signal rate = level changes/sec; bit rate = signal rate × bits per level.)

Transmission impairment — why received ≠ sent

📉
Attenuation
LOSS OF ENERGY

Energy lost overcoming medium resistance (becomes heat); fixed with amplifiers/repeaters. Measured in decibels, which conveniently add along a path: dB = 10 log₁₀(P₂/P₁) (negative = loss). Also usable with voltage: 20 log₁₀(V₂/V₁).

🌀
Distortion
CHANGE OF SHAPE

Frequency components of a composite signal propagate at different velocities → arrive with unequal phase shifts → the composite's shape changes. Worst for wideband signals.

📻
Noise
UNWANTED SIGNAL ADDED

Thermal — random electron motion, unavoidable; induced — motors/appliances as sending antennas, the medium as receiving antenna; crosstalk — coupling between adjacent wires; impulse — spikes (lightning, power switching).

⚖️
SNR
SIGNAL-TO-NOISE RATIO

SNR = P_signal / P_noise (average powers); SNR_dB = 10 log₁₀ SNR. High SNR → signal less corrupted; SNR bounds capacity (→ Shannon, §07).

SOLVED · A signal passes segment 1 (−3 dB), an amplifier (+7 dB), segment 2 (−3 dB). Net effect? dB values add: −3 + 7 − 3 = +1 dB → slight overall gain. (This additivity is exactly why engineers use dB.) SOLVED · Signal 10 mW, noise 1 μW → SNR = 10⁻²/10⁻⁶ = 10,000 → SNR_dB = 10·log₁₀10⁴ = 40 dB.

07

Data-Rate Limits & Network Performance

Data rate depends on three factors: available bandwidth, usable signal levels, and channel noise.

Nyquist — noiseless channel

C = 2 × B × log₂ L  (bps) B in Hz, L = levels. Doubling levels adds only +B bps (log!) — and the receiver must still tell levels apart, so noise caps L in practice. Nyquist is a design formula, not a law of nature for noisy links.

Shannon — noisy channel

C = B × log₂ (1 + SNR)  (bps) Independent of levels/encoding — the hard ceiling. With SNR = 0 (pure noise), C = 0 regardless of bandwidth.
SOLVED · Telephone line: B = 3000 Hz, SNR_dB = 35. SNR = 10^(35/10) = 3162. C = 3000 × log₂(3163) ≈ 3000 × 11.62 ≈ 34.86 kbps. SOLVED · (the "use both" pattern) B = 1 MHz, SNR = 63. Shannon: C = 10⁶ × log₂64 = 6 Mbps (ceiling). Choose a safe target, say 4 Mbps → Nyquist: 4×10⁶ = 2×10⁶×log₂L → log₂L = 2 → L = 4 levels.

Performance metrics

  • Bandwidth — two linked meanings: Hz (frequency range a channel passes) and bps (link speed). More Hz generally buys more bps.
  • Throughput — the measured rate through a point; always ≤ nominal bandwidth (a 1 Mbps link carrying 12,000 × 10,000-bit frames/min ⇒ throughput = 2 Mbps? No — 12,000×10,000/60 = 2 Mbps exceeds capacity, so real throughput saturates at link rate; typical exam version: 12,000 frames/min → 12,000×10,000/60 = 2 Mbps demand on a 10 Mbps link ⇒ throughput 2 Mbps).
  • Latency — time for a complete message to arrive from first bit sent:
Latency = Propagation + Transmission + Queuing + Processing Propagation = distance ÷ propagation speed (per-bit travel). Transmission = message size ÷ bandwidth (time to push all bits onto the wire). Queuing = buffer waits at devices (grows with load). Processing = per-node handling.
SOLVED · 2.5 kB message, 12,000 km link, propagation speed 2.4×10⁸ m/s, bandwidth 1 Gbps. Propagation = 1.2×10⁷ / 2.4×10⁸ = 50 ms. Transmission = 20,000 bits / 10⁹ bps = 0.02 ms. Latency ≈ 50.02 ms → propagation-dominated (short message, fat pipe). For a huge file on a slow link, transmission dominates instead — say which term dominates and why: easy marks.
  • Bandwidth–Delay Product — BW × delay = bits that "fill the pipe" (in flight). A 5 Mbps × 20 ms link holds 100,000 bits; to use full capacity with acknowledgment protocols, the sender's window must cover 2 × BDP (out-and-back).
  • Jitter — delay variation between packets; the enemy of real-time media.
Don't mix the two delay terms. Propagation depends on distance only; transmission depends on message size and bandwidth only. Increasing bandwidth does nothing to propagation delay.

Line Coding — Unipolar & Polar Schemes

Line coding converts a bit sequence into a digital signal. Design goals: minimal bandwidth, no DC component (transformers/couplers block near-zero frequencies; residual DC also wastes power), self-synchronization (transitions let the receiver recover the clock — a mismatched clock misreads bit boundaries), error-detection ability, noise immunity, low complexity. Every waveform below encodes the same stream 0 1 0 0 1 1 1 0.

Unipolar NRZ
1 → +V · 0 → 0 V · NRZ = level held for the full bit interval

Power concentrated near f = 0 → strong DC component; long same-bit runs → no transitions → sync loss. Costly and obsolete.

Polar NRZ-L (Level)
0 → +V · 1 → −V · the level itself is the bit

Average bandwidth B ≈ N/2 (best of the family). Problems: same-bit runs freeze the line (sync); a polarity swap inverts every bit; DC creeps in when 0s and 1s aren't balanced.

Polar NRZ-I (Invert)
1 → transition at bit start · 0 → none · the change is the bit

Differential → polarity-swap immune; every 1 re-syncs the clock. Remaining weakness: long runs of 0s (fixed in practice by scrambling/4B5B — beyond this unit).

Polar RZ (Return-to-Zero)
1 → +V then 0 · 0 → −V then 0 · returns to zero every mid-bit · three levels

Guaranteed per-bit transition solves sync — at the price of double bandwidth and 3 voltage levels (more complexity, more error-proneness). Superseded by Manchester.

Manchester
mandatory mid-bit transition = clock + data · 0 → high-to-low · 1 → low-to-high (IEEE 802.3 convention)

RZ's sync + polar's two levels; zero DC (each bit averages 0). Cost: minimum bandwidth = 2 × NRZ. Used by classic Ethernet (10BASE-T).

Differential Manchester
mid-bit transition always (clock) · 0 → extra transition at bit start · 1 → none at start

Bit = presence/absence of the start transition → polarity-immune like NRZ-I, self-clocking like Manchester. Used by Token Ring.

Transmission Media — Guided

Guided media provide a physical conduit directing the signal (vs unguided = free space/wireless). Metallic media (twisted-pair, coax) carry electric current; optical fiber carries light.

🧬
Twisted-Pair Cable
METALLIC · CHEAPEST · MOST COMMON

Two insulated copper conductors twisted together. Interference and crosstalk hit both wires almost equally, so the receiver — which reads the difference — cancels the noise; more twists per unit length = better cancellation. UTP: unshielded, categories Cat-1…Cat-7 (rising data rate), RJ-45 connector; used in telephone local loops and LANs. STP: metal foil/braid shield per pair — better noise immunity, but bulkier, costlier (mainly IBM/Token-Ring legacy).

🎯
Coaxial Cable
METALLIC · HIGHER FREQUENCY RANGE

Layered: central solid/stranded core → insulating sheath → outer braided/foil conductor (shield and return path) → jacket. Carries higher frequencies than TP but with higher attenuation → needs frequent repeaters. Standardized by RG ratings: RG-59 (cable TV), RG-58 (thin Ethernet), RG-11 (thick Ethernet); BNC connectors (plain/T/terminator). Uses: analog+digital telephone trunks (historic), CATV, traditional Ethernet.

💡
Fiber-Optic Cable
GLASS/PLASTIC · LIGHT · TOTAL INTERNAL REFLECTION

A dense glass core inside a less-dense cladding; light striking the boundary beyond the critical angle reflects back inside — the beam is trapped and guided. Propagation modes: multimode step-index — many rays bounce at abrupt density change, path lengths differ → pulse spreading/distortion; multimode graded-index — density falls gradually from center, rays curve → far less spreading; single-mode — tiny core + focused laser, essentially one horizontal beam → negligible spreading, longest reach, highest rates. Cabling: core/cladding sizes quoted in μm (e.g. 50/125); connectors SC/ST/MT-RJ; sources LED (multimode) or laser (single-mode).
enormous bandwidth (WDM)very low attenuation → repeaters ~50 km apartimmune to EMIcorrosion-resistantlight weighthard to tapinstallation needs expertiseunidirectional per fiber (pairs needed)costly cable + interfaces

Switching — Packet Switching

A switched network moves data through a mesh of switches. Circuit switching (telephony) reserves a dedicated path for the whole session — wasteful for bursty data. Packet switching splits the message into packets; each switch does store-and-forward (receive fully → verify → forward), and resources are granted on demand. Two flavors:

Datagram approach — connectionless

  • Each packet is independent, carries the full destination address; switches consult a routing/forwarding table keyed by destination.
  • Packets of one message can take different paths → possible reordering; buffers full → drops. No setup/teardown. Efficiency high for bursty traffic; delay per packet = transmission + propagation + waits at each switch.
  • This is the Internet's network layer: IP is a datagram network.

Virtual-circuit approach — connection-oriented

  • Setup: a request travels the chosen path; each switch installs an entry (incoming port+VCI → outgoing port+VCI); an acknowledgment flows back assigning VCIs.
  • Data transfer: packets carry a small VCI label, swapped at every switch per its table; all packets ride the same path, in order.
  • Teardown: both ends signal; switches erase the entries. Resources can be reserved at setup (predictable delay) or on demand.
  • Implemented in the data-link layer of WANs (Frame Relay, ATM); the label-swap idea lives on in MPLS.

Data-Link Layer — Introduction & Link-Layer Addressing (up to ARP)

A host-to-host path = a chain of nodes (hosts + routers) and links (the LANs/WANs between). The data-link layer delivers frames hop-to-hop across each link. Services: framing (encapsulate the datagram between header and trailer), flow control (pace a fast sender for a slow receiver), error control (detect/correct or discard-and-let-upper-layers-resend), congestion control (link-scope). Links: point-to-point (dedicated) vs broadcast (shared → needs §13). Sublayers: DLC (data-link control, common to all links) + MAC (media access, only for shared links).

Why a second address type?

IP addresses define host-to-host delivery at internet scope; they cannot steer a frame across one physical link. So the frame has its own addressing. As a datagram crosses the internet: IP source/destination never change; frame MAC source/destination are rewritten at every hop (each router strips the frame, routes the datagram, and builds a new frame for the next link).

  • MAC address — 48 bits = 6 bytes in hex, e.g. 4A:30:10:21:10:1A, assigned to the NIC.
  • Unicast — one recipient. Rule: LSB (least-significant bit) of the first byte = 0 ⇔ second hex digit ∈ {0,2,4,6,8,A,C,E}.
  • Multicast — a group. LSB of first byte = 1 ⇔ second hex digit ∈ {1,3,5,7,9,B,D,F}. Check the bit, not memorized examples: A3:… and 47:… (0x47 = 0100 0111₂) are both multicast.
  • Broadcast — everyone on the link: FF:FF:FF:FF:FF:FF (a special multicast).

ARP — Address Resolution Protocol

The network layer hands down the datagram plus the next-hop IP (its own forwarding decision). ARP supplies the missing piece — the next hop's MAC:

  1. Sender broadcasts an ARP request ("who has IP N? tell me your MAC") — frame destination FF:FF:FF:FF:FF:FF, so every node on the link processes it.
  2. Only the IP's owner answers with a unicast ARP reply carrying its MAC (it can unicast — the requester's MAC was in the request).
  3. Sender caches the mapping (ARP cache, with timeout) and unicasts frames from then on.

Error Detection & Correction — Block Coding, Parity, CRC

Errors & the core idea

  • Single-bit error — exactly one bit flips. Burst error — ≥2 bits flip; length = first-to-last corrupted position (bits between may be intact). Bursts dominate in practice: noise lasts longer than one bit time, and the faster the link, the more bits one noise event clobbers.
  • Redundancy is the only weapon: sender appends bits computed from the data; receiver recomputes and compares. Detection: "damaged or not?" (then discard/rerequest). Correction: also locate the flipped bits — exponentially harder (in an 8-bit unit, a single error has 8 possible positions; two errors, 28).

Block coding

  • Divide the message into datawords of k bits; add r redundant bits → codewords of n = k + r bits.
  • Valid codewords: 2ᵏ out of 2ⁿ possible words. Receiver sees an invalid word ⇒ error. An error that maps one valid codeword onto another valid one is undetectable.
  • Hamming distance d(x,y) = number of differing positions = number of 1s in x ⊕ y. dmin = minimum distance over all valid pairs — the code's whole power is in this number.
Detect ≤ s errors ⇔ dmin = s + 1  ·  Correct ≤ t errors ⇔ dmin = 2t + 1 dmin = 5 → detect 4 or correct 2 (one capability at a time, not both maxima together).

Parity-check code — simplest block code, n = k+1: the extra bit makes total 1s even. dmin = 2 → detects every odd number of errors, misses even counts. Receiver computes the syndrome (checker output over all n bits): 0 → accept dataword, 1 → discard.

SOLVED · d(10101, 11110)? XOR = 01011 → three 1s → d = 3. SOLVED · A code must correct 3 errors. Required d_min = 2·3+1 = 7.

Cyclic Redundancy Check (CRC)

A cyclic code (any rotation of a codeword is a codeword), the standard of LANs/WANs, computed by modulo-2 (XOR, no carries) division:

  1. Append n−k zeros to the dataword.
  2. XOR-divide by the agreed generator (n−k+1 bits, MSB=1). Rule per step: leftmost bit 1 → subtract (XOR) the divisor; leftmost bit 0 → XOR all-zeros; then bring the next bit down.
  3. Remainder (n−k bits) = the CRC; it replaces the appended zeros → codeword.
  4. Receiver divides the received word by the same generator: remainder 0 → accept, else discard.

Worked example — dataword 1001, divisor 1011 (k = 4, n = 7)

1 0 1 0 ← quotient (discarded) ┌───────────────── 1011 │ 1 0 0 1 0 0 0 ← 1001 + three 0s 1 0 1 1 ↓ leftmost 1 → XOR divisor ─────── 0 0 1 0 0 leftmost 0 → XOR 0000 0 0 0 0 ↓ ─────── 0 1 0 0 0 leftmost 0 → XOR 0000 0 0 0 0 ↓ ─────── 1 0 0 0 leftmost 1 → XOR divisor 1 0 1 1 ─────── 0 1 1 remainder = CRC = 110 Codeword = 1 0 0 1 1 1 0 (check: 1001110 ÷ 1011 → remainder 000 ✓)

Polynomial view & generator quality

  • Bits ↔ polynomial: 1011 = x³ + x + 1; degree = position of leftmost 1 = number of CRC bits.
  • A good generator g(x): has ≥2 terms · coefficient of x⁰ is 1 (detects all single-bit errors) · does not divide xᵗ+1 for t up to frame length (catches isolated double errors) · contains factor x+1 (catches all odd-count errors) · degree r ⇒ detects all burst errors of length ≤ r, and bursts of length r+1 with probability 1−(½)^(r−1).
  • Standards: CRC-8 (ATM header), CRC-16/CRC-CCITT (HDLC), CRC-32 (Ethernet, Wi-Fi).
In XOR division there is no borrowing and no "greater than" comparison — the only test is the leftmost bit. Students who long-divide decimally lose the entire numerical.

Media Access Control — CSMA & CSMA/CD

On a broadcast link, simultaneous transmissions collide and destroy each other; a MAC protocol arbitrates access. CSMA is a random-access method: no master, no schedule; each station decides using the medium's state.

CSMA — Carrier Sense Multiple Access

  • Principle: "sense before transmit" — listen; transmit only if idle. Cuts collision probability sharply, can't reach zero.
  • Why not zero: propagation delay. Station B may sense "idle" while A's first bit is still in flight toward it. Vulnerable time = Tp (one end-to-end propagation time): a collision is possible only if another station starts within this window.

Ethernet uses 1-persistent — simple, and its collision detection makes the extra collisions cheap.

Minimum frame condition: Tfr ≥ 2 Tp  ⇒  min frame size = bandwidth × 2Tp Worst case: A's bit almost reaches far-end B (time T_p) when B transmits; the collision takes another T_p to travel back. A must still be transmitting when it arrives — else A would believe the frame succeeded. Hence frame time ≥ round trip.
SOLVED · Classic Ethernet: 10 Mbps, worst 2T_p = 51.2 μs. Min frame = 10⁷ × 51.2×10⁻⁶ = 512 bits = 64 bytes — exactly Ethernet's minimum frame. SOLVED · 1 km bus, propagation 2×10⁸ m/s, 100 Mbps. T_p = 10³/2×10⁸ = 5 μs → min frame = 10⁸ × 10 μs = 1000 bits. Note how a faster network needs a bigger minimum frame — one reason CSMA/CD didn't scale to gigabit shared media.
  • Energy levels a station distinguishes: zero (idle) · normal (one sender) · abnormal (~double — collision). Detection = monitoring energy/voltage while sending.
  • CSMA/CD vs plain ALOHA-family: sensing + early abort → far higher throughput at moderate load. Modern switched full-duplex Ethernet has no shared medium → no collisions → CSMA/CD retired in practice, canonical in exams.
Backoff waits are multiples of the slot time (= 2T_p), not arbitrary microseconds; and the jam signal is sent by the station that detects the collision — its purpose is to guarantee everyone else notices.
